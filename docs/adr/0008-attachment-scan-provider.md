# ADR 0008 — Replaceable attachment scanner with a free cloud adapter

24 October 2026. Scope #27 / US-068. Candidate implementation; production activation remains pending.

The owner selected Bouncer's free tier, requested a replaceable provider and synthetic tests first, and kept the RAM upgrade pending. This amends the default-engine selection in issue #27's 2 October architecture comment, which already required an adapter for a later managed provider. It changes no attachment authorization or accounting policy. ClamAV remains available and is the default for existing configuration; Bouncer must be selected explicitly.

Separate provider decisions from the existing leased worker. The worker validates tenant-owned object keys, private bytes, size and digest before invoking the provider. Only the existing lease-fenced finish routine changes quarantine status. The Bouncer adapter verifies authenticated results against the stored scan id, exact SHA-256 and byte count. Clean requires a clean verdict, no threats and every engine result clean. Suspicious, malicious, incomplete, unknown, timeout and error outcomes never release trusted evidence.

V2 uploads support the existing 10 MiB backend scanner limit; browser uploads remain capped at 4 MB. API requests use a fixed HTTPS origin. Signed uploads must use the explicitly configured Bouncer regional S3 bucket, with no redirects. Only the fixed anonymous filename and file bytes are transmitted; API keys never go to S3, browser bundles or logs. Signed fields live in memory only. Provider output is bounded before parsing, and remote error text is never returned to users or logs.

Migration 0132 stores a private organization/attachment/provider/digest checkpoint and remote id under the current lease. A retry polls the saved id rather than creating another paid-quota event. The free-plan guard refuses paid or unknown tiers and never purchases an upgrade. Exhausted quota defers to the next UTC month without consuming the ordinary retry budget. Pending results defer for 60 seconds; after 24 hours they fail through bounded retries. An ambiguous create/upload outcome stays quarantined for investigation rather than blind resubmission. The provider exposes no underlying signature revision, so the recorded label is only `Bouncer-api-v2`.

Use a separate single-scanner container with a measured synthetic acceptance case under a 192 MiB cap, without ClamAV or other background services. This does not establish spare capacity on the shared production VM or high-volume throughput. The original full-jobs capacity gate stays intact. No production migration, server credential installation, capacity change or deployment is authorized by this decision record.

The provider's published free quota, Mumbai processing region, possible file retention up to 24 hours, metadata retention and terms are recorded in the [operator runbook](../../infra/jobs/README.md). This is not legal approval, a reseller agreement, security certification or a worldwide privacy claim. Owner/legal review and accurate customer disclosures remain necessary before customer-file processing. Acceptance uses synthetic text and the standard harmless EICAR antivirus test string only.
