## UI contract
These are shared screen groups. Implement the portions required by this story; related stories own the remaining behavior. All affected screens need loading, empty, validation, forbidden and conflict states and keyboard-accessible controls.

### UI-22 — Supplier payments
**Routes:** `/o/[org]/purchases/payments; /purchases/payments/new; /purchases/payments/[id]`
**Access:** purchases.read/write + posting capability
**Structure:** Vendor, payment account/date/reference/amount; bill allocation grid; total applied and remaining vendor debit credit; list and immutable detail.
**Actions:** Prepare, approve, record payment, allocate/unapply with history.
**Validation:** No automatic bank payout; cannot apply to another vendor or oversettle due; recheck account/period permissions.
**Expected outcome:** One payment can settle several bills with one cash reduction and correct residuals.

## Database/accounting guards
- [ ] [DB-G01](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Balanced complete journal:** Posting function plus deferred constraint trigger: ≥2 lines, positive debits, debit=credit, state posted at commit.
- [ ] [DB-G06](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Complete subledger:** Each control ledger line has one matching open item; other ledger lines have none; same party/account/amount/side.
- [ ] [DB-G07](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Allocation capacity:** Lock both items in ID order; same tenant/party/control/currency; dates not earlier than source availability; cumulative allocated amount stays within 0..original at every effective-date boundary, not just today.
- [ ] [DB-G10](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Approval validity:** Expected source version/digest and policy snapshot must match; authorized approver; maker-checker; approval invalidated by material edits.
- [ ] [DB-G11](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Cash constraints:** Cash-account mapping matches GL line; avoid negative configured physical cash under concurrent spend; internal transfer legs/classification agree.
