## Acceptance criteria
- [ ] Render issued customer/tax/line snapshots with BDT and Bangla/English Unicode text.
- [ ] Record immutable PDF version and recipient/delivery result separately from settlement/posting.
- [ ] Queue email with retry and prevent duplicate sends from repeated request handling.
- [ ] Delivery failure preserves the journal and allows authorized resend without reissuing revenue.

## UI contract
These are shared screen groups. Implement the portions required by this story; related stories own the remaining behavior. All affected screens need loading, empty, validation, forbidden and conflict states and keyboard-accessible controls.

### UI-14 — Invoice detail
**Routes:** `/o/[org]/sales/invoices/[id]`
**Access:** sales.read
**Structure:** Immutable preview, source/settlement/delivery status strip, total and balance; tabs Details, Payments/Credits, Attachments, Activity, Accounting (permissioned).
**Actions:** Send/resend, export PDF, record collection, issue credit, request reversal.
**Validation:** Financial edit action absent after posting. Reverse shows affected allocations and locked-period restrictions.
**Expected outcome:** The PDF and UI show the original issued contact/tax snapshot; all linked settlements explain residual balance.
