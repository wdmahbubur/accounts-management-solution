## Acceptance criteria
- [ ] Support staged CSV/XLSX account/date/amount/reference mapping with preview and row errors.
- [ ] Exact file/provider transaction keys are idempotent and ambiguous equal-value fingerprints require review.
- [ ] Normalize signs, dates and BDT values without silently dropping legitimate equal transactions.
- [ ] Importing observations creates no GL entries and unsafe files are rejected/quarantined.

### UI-28 — Bank statement import wizard
**Routes:** `/o/[org]/banking/import`
**Access:** banking.write
**Structure:** Choose account → upload CSV/XLSX → map date/description/debit/credit or signed amount → preview rows → warnings → confirm.
**Actions:** Save mapping, validate, import, go to reconciliation.
**Validation:** Exact file/provider IDs de-duplicate; fingerprint collisions prompt review; row numbers and raw values retained.
**Expected outcome:** Importing a statement alone creates no GL journal and cannot inflate cash.
