## Acceptance criteria
- [ ] Require reconciled opening/closing balances and zero unexplained difference before finalize.
- [ ] Protect finalized match sets and overlapping reconciliation coverage.
- [ ] Reopen requires reason, elevated capability and audit while retaining previous evidence.
- [ ] A reconciled payment cannot be reversed until the authorized dependency-resolution path completes.

## UI contract
These are shared screen groups. Implement the portions required by this story; related stories own the remaining behavior. All affected screens need loading, empty, validation, forbidden and conflict states and keyboard-accessible controls.

### UI-29 — Reconciliation workspace
**Routes:** `/o/[org]/banking/reconciliations; /reconciliations/[id]`
**Access:** banking.read/write; separate finalization capability
**Structure:** Statement balance header; left bank rows, right book entries; selected match amount and remaining capacities; suggestions; outstanding items; closing difference panel.
**Actions:** Match/unmatch in draft, split match, create reviewed missing fee/receipt, finalize, reopen with reason.
**Validation:** Zero unexplained difference; same account/direction; no reused capacity; finalized sessions immutable without audited reopen.
**Expected outcome:** A matching action never duplicates an existing posting and cannot force zero by hiding unexplained bank movements.
