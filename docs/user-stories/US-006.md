## UI contract
These are shared screen groups. Implement the portions required by this story; related stories own the remaining behavior. All affected screens need loading, empty, validation, forbidden and conflict states and keyboard-accessible controls.

### UI-02 — Authentication, recovery and invitation
**Routes:** `/auth/sign-in; /auth/sign-up; /auth/recover; /auth/verify; /invite/[token]`
**Access:** Public or invited user
**Structure:** One focused form per route; email/password or configured auth method; terms/privacy links; invite company and proposed role; accessible error summary.
**Actions:** Sign in, request reset, verify email, accept invite, resend verification with limits.
**Validation:** Generic account-enumeration-safe errors; expired invite state; no financial content before verified session. Invite email/identity and role must match the server record.
**Expected outcome:** Expired or revoked invitation cannot grant membership, and switching accounts cannot accept another person's invite silently.

### UI-51 — Personal profile and security
**Routes:** `/settings/profile; /settings/security`
**Access:** Signed-in user
**Structure:** Display name/locale/timezone, password/auth settings, MFA/session management supported by chosen provider.
**Actions:** Update profile, change credential, enroll MFA, revoke sessions.
**Validation:** Profile settings cannot assign roles; financial actor snapshots remain stable after display-name change.
**Expected outcome:** Security changes do not affect another user and sensitive operations require the configured recent authentication.

## AI implementation procedure
1. Inspect the current branch, linked prerequisites and source sections. State the bounded plan in the issue/PR; do not reimplement completed modules.
2. Use a branch such as `feat/us-NNN-short-title`. Make reviewed versioned migrations where needed; preserve unrelated code and source documents.
