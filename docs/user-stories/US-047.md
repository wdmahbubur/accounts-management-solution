## UI contract
These are shared screen groups. Implement the portions required by this story; related stories own the remaining behavior. All affected screens need loading, empty, validation, forbidden and conflict states and keyboard-accessible controls.

### UI-32 — Journal register
**Routes:** `/o/[org]/accounting/journals`
**Access:** ledger.read
**Structure:** Date, journal/source number, type, memo, debit/credit total, creator, posted/reversal label; filters by account/source/period.
**Actions:** Create manual journal, view, export, request reversal.
**Validation:** Journal list contains posted history; transaction-local building states never appear as successful records.
**Expected outcome:** Original and reversal both remain available, with date-specific effects.

### UI-33 — Manual journal editor and detail
**Routes:** `/o/[org]/accounting/journals/new; /journals/[id]`
**Access:** journal.write/post; ledger.read
**Structure:** Date/memo/evidence; line grid account, party where controlled, cost center, debit, credit; live difference and cash classification; immutable detail after post.
**Actions:** Add/remove draft rows, save, submit/post, reverse.
**Validation:** Difference must equal 0.00; one side per line; forbid unmanaged control accounts; recent permission/period check.
**Expected outcome:** The API rejects an unbalanced journal even when the UI checks are bypassed.

## Database/accounting guards
- [ ] [DB-G01](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Balanced complete journal:** Posting function plus deferred constraint trigger: ≥2 lines, positive debits, debit=credit, state posted at commit.
- [ ] [DB-G03](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Immutable posted record:** Reject UPDATE/DELETE of posted source financial fields, journal headers/lines, open-item amounts and posted child snapshots; no client TRUNCATE privilege.
- [ ] [DB-G06](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Complete subledger:** Each control ledger line has one matching open item; other ledger lines have none; same party/account/amount/side.
- [ ] [DB-G09](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Reversal integrity:** Source is posted and not already reversed; exact swapped amounts; correct reversal period; dependent settlements/reconciliation resolved.
- [ ] [DB-G10](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Approval validity:** Expected source version/digest and policy snapshot must match; authorized approver; maker-checker; approval invalidated by material edits.
