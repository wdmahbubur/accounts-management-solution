# US-037 — Implement dated source reversals and dependency safeguards

**Epic:** [E05 #6](https://github.com/wdmahbubur/accounts-management-solution/issues/6)  |  **Milestone:** M2 — Tested accounting engine  |  **Priority:** P0

## Acceptance criteria
- [ ] Create a new exact opposite journal linked to the original source and preserve both entries.
- [ ] Allow one effective reversal with authorized reason in an open period.
- [ ] Require settlement unapply and authorized reconciliation reopen where dependencies exist.
- [ ] Reject partial arbitrary source rewrites, second reversals and original-date substitution in locked books.

## Database/accounting guards
- [ ] [DB-G03](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Immutable posted record:** Reject UPDATE/DELETE of posted source financial fields, journal headers/lines, open-item amounts and posted child snapshots; no client TRUNCATE privilege.
- [ ] [DB-G04](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Locked-period safety:** Lock/check fiscal year and period before posting or settlement; period-lock command uses compatible lock order so race cannot bypass close.
- [ ] [DB-G08](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Allocation reversal:** One full reversal per allocation; date ≥ allocation date; open-period check; append-only evidence.
- [ ] [DB-G09](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Reversal integrity:** Source is posted and not already reversed; exact swapped amounts; correct reversal period; dependent settlements/reconciliation resolved.

## AI implementation procedure
1. Inspect the current branch, linked prerequisites and source sections. State the bounded plan in the issue/PR; do not reimplement completed modules.
2. Use a branch such as `feat/us-NNN-short-title`. Make reviewed versioned migrations where needed; preserve unrelated code and source documents.
3. Implement contracts, authorization and DB/domain behavior before wiring financial UI. Add negative, replay and cross-tenant tests; use independent connections for races.
4. Run the repository's actual documented checks. Record exact commands, results, commit and limitations; never invent scripts, screenshots, test output or reviewer approval.
5. Open a focused PR referencing this issue. Add closure wording only when all acceptance criteria and dependencies are satisfied. Do not deploy production or move money without separate authorization.
