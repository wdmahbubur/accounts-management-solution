## Acceptance criteria

- [ ] Reopen retains prior snapshots, records reason and requires explicit reclose review.

## UI contract
These are shared screen groups. Implement the portions required by this story; related stories own the remaining behavior. All affected screens need loading, empty, validation, forbidden and conflict states and keyboard-accessible controls.

### UI-42 — Period close workspace
**Routes:** `/o/[org]/accounting/periods; /periods/[id]`
**Access:** periods.lock/reopen
**Structure:** Period calendar, open/locked status, checklist with TB/control/bank/tax/cash exceptions, pending approvals and report snapshots; lock history.
**Actions:** Run checks, resolve exceptions, lock, reopen with reason/reauthentication.
**Validation:** Posting-versus-lock race handled in DB; unresolved hard checks disable close; no invisible administrator bypass.
**Expected outcome:** A locked month rejects backdated journal, allocation and allocation reversal through every entry path.

## Database/accounting guards
- [ ] [DB-G04](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Locked-period safety:** Lock/check fiscal year and period before posting or settlement; period-lock command uses compatible lock order so race cannot bypass close.
- [ ] [DB-G10](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Approval validity:** Expected source version/digest and policy snapshot must match; authorized approver; maker-checker; approval invalidated by material edits.
- [ ] [DB-G13](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Reconciliation capacity:** Lock statement and GL rows; same bank account/direction; matched sums ≤ amount; finalized sessions protected; no overlapping conflicting finalized coverage.
