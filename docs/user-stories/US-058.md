- [ ] Printable/export-ready statement totals reconcile to controls and preserve generation context.

## UI contract
These are shared screen groups. Implement the portions required by this story; related stories own the remaining behavior. All affected screens need loading, empty, validation, forbidden and conflict states and keyboard-accessible controls.

### UI-41 — Customer/vendor statement report
**Routes:** `/o/[org]/reports/statements`
**Access:** Scoped party financial read
**Structure:** Party selector and AR/AP side; date range, opening, invoice/bill, receipts/payments, credits, allocations, closing; letter/PDF preview.
**Actions:** Export/send statement after explicit recipient review.
**Validation:** No accidental cross-party aggregation; statement sending is an external action with visible destination.
**Expected outcome:** Opening plus movements equals closing and displayed allocations explain remaining items.

## Database/accounting guards
- [ ] [DB-G06](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Complete subledger:** Each control ledger line has one matching open item; other ledger lines have none; same party/account/amount/side.
- [ ] [DB-G07](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Allocation capacity:** Lock both items in ID order; same tenant/party/control/currency; dates not earlier than source availability; cumulative allocated amount stays within 0..original at every effective-date boundary, not just today.
- [ ] [DB-G08](https://github.com/wdmahbubur/accounts-management-solution/blob/master/docs/03-database-design.md) **Allocation reversal:** One full reversal per allocation; date ≥ allocation date; open-period check; append-only evidence.
