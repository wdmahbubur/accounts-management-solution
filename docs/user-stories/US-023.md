# US-023 — Allocate opposite open items with historical and concurrent capacity checks

**Epic:** [E03 #4](https://github.com/wdmahbubur/accounts-management-solution/issues/4)  |  **Milestone:** M2 — Tested accounting engine  |  **Priority:** P0
**Scope:** V1 implementation / review gate

## User story
As a **accountant**, I want to **settle invoices without overusing receipts or rewriting past balances**.

## Acceptance criteria
- [ ] Validate same organization, party, currency, control and opposite direction.
- [ ] Lock affected item IDs in a deterministic order and enforce capacity at every effective-date boundary.
- [ ] Support partial and many-document allocation with no second income/expense journal.
- [ ] Reject backdated credit reuse that over-allocates any historical period and prove two-connection races safe.
