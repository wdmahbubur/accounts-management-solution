# Deferred-billing SaaS foundation - 21 October 2026

Scope: the owner's explicit request to defer actual paid billing, retain a replaceable adapter and supply approved paid plans/limits later. This is a focused partial implementation for US-074/US-075 (#91/#92), stacked on PR #186. It does not close either story or claim their original paid-provider acceptance criteria are complete. Live prerequisites #23 and #28 are closed; #42, #44 and #45 remain open with verification/review gates. Their application contracts exist, and this slice adds no financial posting or entitlement mutation path.

The provider interface has checkout, portal and raw-body verification operations. Its installed disabled adapter rejects all three. Unsupported provider configuration fails closed. A protected Subscription screen shows four actual active members and no configured paid plan in the synthetic Golden alpha company. There is no price/seat/trial default and no purchase control to mislead users.

Migration **0120** adds only a guarded read function over the existing plans/subscriptions/membership model. Canonical migration verification completed through 119 files. No plan, paid subscription, billing event or journal was created by the summary read. Runtime financial DML grants were not expanded. The checkout API checks authentication, capability, origin and company context before returning `409 BILLING_DISABLED`; the webhook endpoint returns 503 without acknowledging or processing supplied events.

The runtime connection pool is bounded at two, with transaction-local actor identity preserved. The previous one-connection pool could make concurrent layout/auth/command requests wait behind each other during the remote-database test. The new ordinary-role concurrent HTTP check verifies Owner success, Billing denial and nonmember denial over three parallel rounds. No authentication or membership result is cached across requests. This is a small concurrency regression, not the 100-company/100k-lines-per-company release benchmark.
